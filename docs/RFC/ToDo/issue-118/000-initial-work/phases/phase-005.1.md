# Subphase 005.1: Remediation for Phase 005 (Cross-run store-only resolution)

## Context
This subphase was generated by the phase verifier after reviewing `phase-005.md`.

The **code** for Phase 005 is implemented correctly. `ArtifactRegistry.resolve_ref_async`
(`penguiflow/planner/artifact_registry.py:381-394`) now replaces the bare
`if record is None: return None` early-return with the namespace-gated cross-run store-fallback,
exactly as specified (record-miss -> `get_metadata` -> namespace gate -> hydrate). All of the
following were verified against the real code and pass:

- Record MISS first tries the record-based path (record lookup wins), then a store fallback ONLY when
  the store exposes `get_metadata` (`getattr(artifact_store, "get_metadata", None)`, called only if
  `callable`).
- Namespace-gated: proceeds only when `getattr(meta_ref, "namespace", None) == "penguiflow_ui_component"`;
  otherwise returns `None` (caller raises `Unknown artifact_ref`).
- The gate literal `"penguiflow_ui_component"` (`artifact_registry.py:389`) matches the single writer
  exactly (`penguiflow/rich_output/nodes.py:543`) — confirmed by grep (only those two occurrences in
  the package, outside tests).
- Scope-checking preserved: `ScopedArtifacts.get_metadata` (`penguiflow/artifacts.py:329-336`) is itself
  `_check_scope`-protected; out-of-scope ids yield `meta_ref is None` -> `return None`, no leak, no
  byte download.
- Sync `resolve_ref` (`artifact_registry.py:345-365`) is unchanged — no async I/O added.
- The default inline path and existing in-run/resume behavior are unchanged.

Verification gates all pass:

## The single issue: the phase ships NO tests for its own new branch

The new record-ABSENT cross-run branch (`artifact_registry.py:382-394`) is **not exercised by any
committed test**. Phase 005's Exit Criteria are written as concrete, demonstrable behavioral scenarios
(cross-run composition resolves; scope boundary refuses; namespace gate refuses; bogus id raises;
inline/NoOp inert), and the parent plan (`plan.md` Verification, lines ~510-520) enumerates these as
*new tests* for change 3a. No such tests exist.

Why this is not already covered:
- The only `resolve_ref_async` tests in `tests/test_artifact_registry.py`
  (`test_resolve_ref_async_rehydrates_ui_component_from_store_after_snapshot` :68,
  `test_resolve_ref_async_inline_mode_never_hits_store` :119) belong to **Phase 004** (the
  record-PRESENT resume path). In both, `from_snapshot` rebuilds the record, so `_records_by_ref`
  HAS the record — the Phase 005 `record is None` branch is never entered.
- Their stub, `_ScopedStoreStub` (`tests/test_artifact_registry.py:55-65`), deliberately exposes only
  `download` and **no `get_metadata`**. Even if it reached the new branch, `get_meta` would be `None`,
  short-circuiting before the gate. So it structurally cannot test the gate.
- `tests/test_artifacts.py` `test_get_metadata_*` (:1048-1102) are pre-existing unit tests of the
  `ScopedArtifacts.get_metadata` primitive in isolation; they are never wired through `resolve_ref_async`.
- Remaining phases 006-010 are `list_artifacts` dedup, playground backend, Svelte frontend, template
  wiring, and docs respectively — **none is a testing phase and none covers cross-run resolution**.
  Phase 004's own notes (lines 150-153) explicitly state Phase 005 owns the cross-run fallback test.
  If these tests are not added in this phase, they will never be added.

Per the precedent set by Phase 004 (which added its own focused unit tests to satisfy its exit
criteria), Phase 005 must do the same for the record-ABSENT branch.

## Issues to Resolve

### Issue 1: No test for the cross-run record-ABSENT happy path (hydrate)
- **Type**: Missing Test (Exit Criteria not demonstrated)
- **Location**: `tests/test_artifact_registry.py` (new test); exercises
  `penguiflow/planner/artifact_registry.py:382-394`.
- **Description**: No test builds a FRESH `ArtifactRegistry` (no record for the id, no snapshot
  restore) and resolves a bare store id through `resolve_ref_async` with a store that exposes a
  scope-checked `get_metadata`.
- **Expected Behavior**: With `meta_ref.namespace == "penguiflow_ui_component"` and the bytes present
  in the store, `resolve_ref_async` returns a valid `{"component", "props"}` payload (NOT `None`),
  having called `get_metadata` first and then `download`/`get`.
- **Current Behavior**: Untested. The existing `resolve_ref_async` tests only cover the record-PRESENT
  resume path.
- **Suggested Approach**: Add a stub store class (or extend a new one — do NOT weaken the Phase 004
  `_ScopedStoreStub`, which is intentionally `get_metadata`-less) exposing BOTH `get_metadata(id) ->
  ArtifactRef|fake-meta` and `download(id) -> bytes`. Store the full Phase 002 payload dict as JSON
  bytes. Assert: result is a component payload; `get_metadata` was called before `download`; the
  registry had no record for the id (`id not in registry._records_by_ref`).

### Issue 2: No negative test for the namespace gate (Finding 3)
- **Type**: Missing Test (Exit Criteria not demonstrated)
- **Location**: `tests/test_artifact_registry.py` (new test); exercises the
  `getattr(meta_ref, "namespace", None) != "penguiflow_ui_component"` branch
  (`artifact_registry.py:389-390`).
- **Description**: No test confirms that bytes which DO parse as a component but were written under a
  DIFFERENT namespace are refused.
- **Expected Behavior**: `get_metadata` returns a meta whose `namespace` is something other than
  `"penguiflow_ui_component"`; `resolve_ref_async` returns `None` and **does not** download the bytes.
- **Current Behavior**: Untested — this is the central Finding-3 defense and has zero coverage.
- **Suggested Approach**: Stub `get_metadata` to return a meta object with
  `namespace="some_other_namespace"` while the blob (component-shaped JSON) is present. Assert the
  result is `None` AND that `download`/`get` was never invoked (gate must short-circuit before any byte
  fetch).

### Issue 3: No negative test for the out-of-scope / `get_metadata is None` path (scope boundary)
- **Type**: Missing Test (Exit Criteria not demonstrated)
- **Location**: `tests/test_artifact_registry.py` (new test); exercises `meta_ref is None`
  (`artifact_registry.py:389`).
- **Description**: No test confirms the scope boundary: a cross-session / out-of-scope id yields
  `meta_ref is None` -> `return None`, with no byte leak.
- **Expected Behavior**: `get_metadata` returns `None` (mirrors `ScopedArtifacts.get_metadata`'s
  `_check_scope` returning `None` for out-of-scope refs); `resolve_ref_async` returns `None` and never
  downloads.
- **Current Behavior**: Untested.
- **Suggested Approach**: Stub `get_metadata` to return `None` for the id while a blob exists. Assert
  result `None` and `download` not called. (Optionally also assert the end-to-end raise via
  `resolve_artifact_refs_async`, which turns a `None` into `RuntimeError("Unknown artifact_ref ...")`.)

### Issue 4: No test that a bogus/hallucinated id still raises `Unknown artifact_ref`
- **Type**: Missing Test (Exit Criteria not demonstrated)
- **Location**: `tests/test_artifact_registry.py` (new test); exercises the loud-failure contract via
  `resolve_artifact_refs_async` (`artifact_registry.py:467-520`, raise at :496-497).
- **Description**: No test confirms a genuinely unknown id (no record, `get_metadata` -> `None`) still
  surfaces as a loud `RuntimeError`, not a silent wrong answer.
- **Expected Behavior**: Passing `{"artifact_ref": "bogus_id"}` to `resolve_artifact_refs_async` with a
  store whose `get_metadata` returns `None` raises `RuntimeError` containing `"Unknown artifact_ref"`.
- **Current Behavior**: Untested for the store-backed code path.
- **Suggested Approach**: Use `pytest.raises(RuntimeError, match="Unknown artifact_ref")` around
  `resolve_artifact_refs_async({"artifact_ref": "bogus_id"}, ...)`.

### Issue 5 (recommended, lower priority): No test that inline/NoOp (no `get_metadata`) is inert
- **Type**: Missing Test (Exit Criteria not demonstrated)
- **Location**: `tests/test_artifact_registry.py` (new test); exercises
  `callable(get_meta) is False` (`artifact_registry.py:387-388`).
- **Description**: The inline/NoOp inertness criterion is partially implied by the existing Phase 004
  `test_resolve_ref_async_inline_mode_never_hits_store`, but that test takes the record-PRESENT path
  (`record.artifact_id is None`), not the record-ABSENT branch. A direct test of "store has no
  `get_metadata` attribute -> branch returns `None`" is absent.
- **Expected Behavior**: With a store object lacking `get_metadata`, the record-ABSENT branch sets
  `meta_ref = None` and returns `None`; nothing is downloaded.
- **Current Behavior**: Not directly tested for the record-ABSENT branch.
- **Suggested Approach**: Resolve a store id against a fresh registry using a store that exposes only
  `download` (the existing `_ScopedStoreStub` is perfect here); assert `None` and `download` not called.

### How each new test enters the record-ABSENT branch
Every new test builds a **FRESH** `ArtifactRegistry()` (no `from_snapshot`, no
`register_*`), so `_records_by_ref` is empty and `record is None` is guaranteed. Each test
asserts `artifact_id not in registry._records_by_ref` up front to prove the record-PRESENT
path cannot be taken, and asserts the store's `get_metadata`/`download` call lists so the
branch is demonstrably exercised (non-tautological).

- **Issue 1 — `test_resolve_ref_async_cross_run_hydrates_from_store`** (happy path):
  store returns a meta with `namespace == "penguiflow_ui_component"` and component-shaped
  JSON bytes. Asserts the result is a real `{"component","props"}` payload, and that the
  ordered `calls` list is exactly `["get_metadata:<id>", "download:<id>"]` — i.e.
  `get_metadata` ran BEFORE `download`. Also re-asserts the id stays absent from
  `_records_by_ref` (the branch does not synthesize a record).
- **Issue 2 — `test_resolve_ref_async_cross_run_namespace_gate_refuses`** (namespace gate):
  `get_metadata` returns a meta with `namespace="some_other_namespace"` while the blob is
  still a valid component. Asserts result is `None`, `metadata_calls == [id]`, and crucially
  `downloaded == []` — the gate short-circuits before any byte fetch.
- **Issue 3 — `test_resolve_ref_async_cross_run_out_of_scope_refuses`** (scope boundary):
  `get_metadata` returns `None` (mirrors `ScopedArtifacts.get_metadata`'s out-of-scope
  `_check_scope` return) while a blob exists. Asserts `None`, `metadata_calls == [id]`,
  `downloaded == []`.
- **Issue 4 — `test_resolve_artifact_refs_async_bogus_id_raises`** (loud failure):
  drives the public `resolve_artifact_refs_async({"artifact_ref": "bogus_id"}, ...)` with a
  store whose `get_metadata` returns `None`. Asserts `pytest.raises(RuntimeError,
  match="Unknown artifact_ref")`, and that the store was genuinely consulted
  (`metadata_calls == ["bogus_id"]`) but nothing downloaded.
- **Issue 5 — `test_resolve_ref_async_cross_run_inline_noop_store_is_inert`** (inertness):
  uses the existing Phase 004 `_ScopedStoreStub` (no `get_metadata`) against a fresh
  registry. Asserts `getattr(store, "get_metadata", None) is None` (so `callable(get_meta)`
  is `False`), result is `None`, and `download` was never called.

### Key Considerations
- I used a real `penguiflow.artifacts.ArtifactRef` (not a fake/duck-typed object) as the
  `get_metadata` return value. The production gate reads `getattr(meta_ref, "namespace", None)`,
  and `ArtifactRef.namespace` is a real field, so this is both faithful to production and
  keeps mypy happy (the stub's `get_metadata` is annotated `-> ArtifactRef | None`, matching
  `ScopedArtifacts.get_metadata`).
- The combined ordered `calls` list in `_MetadataStoreStub` is what makes the happy-path test
  non-tautological: it proves `get_metadata` precedes `download`, which is exactly the
  gate-before-fetch ordering the phase requires.
- I deliberately gave the namespace-gate and out-of-scope tests a present, valid blob so the
  only thing preventing resolution is the gate / scope check — proving the gate (not a missing
  blob) is what refuses the request.
- I did NOT add `get_metadata` to `_ScopedStoreStub`, honoring the explicit Exit-Criteria
  constraint; Issue 5 reuses it precisely because its `get_metadata`-less shape is the
  inline/NoOp case under test.

### Assumptions
- `_records_by_ref` is the correct private attribute to assert record-absence against (it is
  the dict `resolve_ref_async` consults at line 381). This matches the phase's own guidance.
- A fresh `ArtifactRegistry()` with no registration/snapshot is an adequate stand-in for a
  "separate `planner.run()` call in the same session" for the purpose of exercising the
  record-ABSENT branch. The branch only depends on `record is None`, so this is sufficient.
- `mime_type="application/json"` on the meta `ArtifactRef` is irrelevant to the branch (only
  `namespace` is gated); it is set merely for realism.
